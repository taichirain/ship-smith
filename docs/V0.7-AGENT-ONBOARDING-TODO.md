# ShipSmith v0.7 开发任务清单

> 版本：v0.7 执行清单
> 日期：2026-05-09
> 关联文档：`docs/V0.7-AGENT-ONBOARDING-PLAN.md`

---

## 1. 使用方式

这份文档只做一件事：

**把 `v0.7` 的 Agent 接入体验升级拆成可执行任务。**

原则：
- 继续坚持 Agent 作为唯一正式部署执行面
- 优先把“手动接入”压缩成“复制一条命令”
- SSH 只做安装辅助，不做长期远程运维
- 优先补齐接入反馈和失败提示，不做花哨自动化

建议节奏：
- 先做 `v0.7.0`
- 让多数用户用一键安装命令完成接入
- 再评估 `v0.7.1` 的 SSH 辅助安装是否值得继续推进

## 2. v0.7.0

目标：把 Agent 安装从文档步骤变成产品内主流程。

### 2.1 接入引导页

#### API / 服务层
- [ ] 梳理项目创建成功后的接入态数据
  建议至少包含：
  - `project_id`
  - `agent_id`
  - `agent_token`
  - `core_url`
  - `install_command`
  - `manual_steps_available`
- [ ] 增加接入页所需聚合接口
  建议：`GET /api/v1/projects/{id}/onboarding`
- [ ] 明确 `agent_token` 的展示策略
  建议：
  - 创建时可见
  - 接入页可再次生成安装命令
  - 如需重新暴露 token，则必须显式 rotate

完成定义：
- 前端无需拼很多零散接口，就能渲染完整接入流程

#### Web
- [ ] 新增项目创建成功后的专用接入页
- [ ] 展示：
  - Agent ID
  - Core URL
  - 一键安装命令
  - 手动安装步骤入口
  - 当前在线状态
- [ ] 提供复制安装命令按钮
- [ ] 提供“重新生成命令”或“刷新命令”入口
- [ ] 如果 Agent 已在线，明确展示成功态并给出下一步入口

完成定义：
- 用户创建项目后不会回到空白项目页，而是直接进入“下一步怎么接入”

### 2.2 一键安装命令生成

#### API / 服务层
- [ ] 设计安装命令生成接口
  建议：`POST /api/v1/projects/{id}/install-command`
- [ ] 明确命令生成入参
  建议至少支持：
  - install mode
  - target platform hint
- [ ] 输出统一结构
  建议包含：
  - `command`
  - `expires_at`
  - `manual_install_url`
  - `notes`
- [ ] 评估安装命令是否采用短时 token 或一次性安装票据
- [ ] 限制命令有效期，避免长期裸露敏感参数

完成定义：
- 页面和未来 CLI 都能复用同一套命令生成逻辑

#### 安全策略
- [ ] 梳理安装命令中敏感信息暴露面
- [ ] 避免在日志中落完整 token
- [ ] 明确命令复制、刷新、失效后的行为

完成定义：
- 一键安装命令不会成为长期凭据泄露点

### 2.3 安装脚本与安装包

#### Agent / 安装脚本
- [ ] 整理统一安装脚本入口
  建议支持：
  - 下载 Agent 二进制
  - 写入 env 配置
  - 安装 systemd service
  - 启动 Agent
- [ ] 安装前检查基础依赖：
  - `curl` 或等价下载工具
  - `systemd`
  - 写入目标目录权限
- [ ] 安装输出改成更易读的阶段式提示
  例如：
  - downloading
  - configuring
  - installing service
  - starting agent
  - waiting for check-in
- [ ] 明确失败退出码和错误文案

完成定义：
- 用户执行安装命令后，能看懂脚本现在进行到哪一步

#### 交付方式
- [ ] 明确安装脚本托管位置
- [ ] 明确 Agent 包下载地址生成方式
- [ ] 确保开发环境与生产环境都能走通安装流程

完成定义：
- 安装命令不是 demo 文本，而是真能落到可下载产物

### 2.4 手动安装 fallback

#### Docs / API / Web
- [ ] 在接入页保留手动安装步骤入口
- [ ] 手动步骤至少覆盖：
  - 下载 Agent
  - 写入配置
  - 启动服务
  - 验证回连
- [ ] 让手动步骤与一键安装命令使用同一批参数来源

完成定义：
- 一键安装失败时，用户有明确 fallback，不需要跳出系统翻 README

### 2.5 Agent 在线状态反馈

#### API / 服务层
- [ ] 增加接入状态查询接口或扩展现有项目状态接口
- [ ] 明确接入成功判定规则
  建议：
  - Agent 首次 heartbeat 到达
  - 或 Agent 领取能力已可用
- [ ] 记录首次上线时间

完成定义：
- 系统能稳定判断“已经装好”还是“仍未接入”

#### Web
- [ ] 接入页轮询 Agent 在线状态
- [ ] 支持状态：
  - waiting
  - online
  - failed
  - expired
- [ ] 如果 1 分钟内未在线，展示常见排查建议
  例如：
  - 服务未启动
  - token 失效
  - Core URL 不可达
  - 端口或网络问题

完成定义：
- 用户执行安装命令后，不需要靠猜测判断接入是否成功

## 3. v0.7.1

目标：增加受限的 SSH 辅助安装能力，但不偏离产品主线。

### 3.1 SSH 辅助安装任务模型

#### API / 服务层
- [ ] 设计 SSH 安装任务接口
  建议：`POST /api/v1/projects/{id}/ssh-install`
- [ ] 明确最小入参：
  - `host`
  - `port`
  - `username`
  - `auth_type`
  - `password` 或 `private_key`
- [ ] 定义 SSH 安装任务状态
  建议：
  - `queued`
  - `connecting`
  - `running`
  - `success`
  - `failed`
- [ ] 增加任务查询接口
- [ ] 增加任务日志查询接口

完成定义：
- SSH 安装过程可以被页面展示，而不是黑盒提交

#### 安全边界
- [ ] 明确 SSH 凭据只用于本次任务
- [ ] 不持久化保存原始密码或私钥
- [ ] 脱敏记录任务日志
- [ ] 明确超时和失败后的销毁策略

完成定义：
- SSH 辅助安装不会自然演变成长期凭据托管能力

### 3.2 SSH 安装执行器

#### 服务层
- [ ] 选定 SSH 执行实现方式
- [ ] 支持直连 Linux 主机
- [ ] 支持执行远端安装脚本
- [ ] 支持回收远端标准输出和错误输出
- [ ] 明确 sudo 处理策略
  建议第一版只支持已具备安装权限的用户

完成定义：
- 第一版能稳定完成“连上去并跑安装脚本”，而不是处理所有运维细节

#### 范围限制
- [ ] 第一版明确不支持：
  - jump host
  - 批量安装
  - 远程终端
  - 远程部署
  - 远程文件管理
- [ ] 在产品文案和接口语义中体现“仅安装 Agent”

完成定义：
- 实现边界和用户预期保持一致

### 3.3 SSH 安装页面

#### Web
- [ ] 在接入页增加“高级方式：通过 SSH 安装 Agent”
- [ ] 表单采集：
  - host
  - port
  - username
  - password 或 private key
- [ ] 提交后展示安装进度视图
- [ ] 展示远端日志片段
- [ ] 成功后自动跳转或刷新接入状态
- [ ] 失败后明确提示失败阶段和下一步建议

完成定义：
- 用户能理解 SSH 安装只是一次性辅助流程，不是长期管理入口

## 4. 共用能力

目标：减少 L1 和 L2 的重复实现。

### 4.1 安装参数统一

#### API / 服务层
- [ ] 抽出统一安装参数生成逻辑
- [ ] 保证一键安装命令和 SSH 安装共用：
  - Agent 下载地址
  - Core URL
  - token 或安装票据
  - service 配置模板

完成定义：
- 两条接入路径底层一致，避免行为分叉

### 4.2 安装结果与排障建议

#### 服务层 / Web
- [ ] 统一安装失败分类
  建议首批覆盖：
  - download failed
  - permission denied
  - systemd unavailable
  - service start failed
  - core unreachable
  - invalid token
- [ ] 为每类失败提供固定建议文案
- [ ] 在一键安装和 SSH 安装两条路径上复用

完成定义：
- 用户看到的是一致的失败解释，而不是两套互相矛盾的提示

## 6. 验收清单

- [ ] 用户创建项目后可直接进入接入引导页
- [ ] 页面可生成并复制一键安装命令
- [ ] 用户执行命令后，Agent 能自动安装并回连
- [ ] 接入页能看到实时在线状态反馈
- [ ] 一键安装失败时，有明确 fallback 和排障建议
- [ ] SSH 辅助安装只用于安装 Agent，不承担部署功能
- [ ] SSH 凭据不被长期保存

---

## 7. 建议优先级

建议开发顺序：

1. 接入引导页
2. 一键安装命令生成接口
3. 安装脚本与安装包稳定化
4. Agent 在线状态反馈
5. 手动安装 fallback
6. SSH 辅助安装任务模型
7. SSH 安装执行器与页面

如果中途要缩范围，优先保留：
- 一键安装命令
- 接入页
- 在线状态反馈
- 手动 fallback

可延后的是：
- SSH 辅助安装
- 更丰富的 SSH 日志展示
- 更细的安装任务历史
